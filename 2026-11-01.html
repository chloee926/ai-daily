01

AI 新名词

共享 token 额度（Shared Token Allowance）

OpenAI 从 12 月起把 ChatGPT 与 Codex 的用量额度合并成一个池子，统一按 token 计量，而不是按消息条数。模型越强、任务越复杂，扣得越快；只有 Instant 即时聊天不计入。含义是：智能体每跑一次多步任务，都开始和聊天抢同一份预算，用户第一次能清楚看到"干一件事"的真实成本。

机器可读标记（Machine-readable Marking / 隐形水印）

xAI 从 11 月 7 日起给 Grok API 输出的文本默认加一层看不见的水印。它不往文字里塞隐藏字符，而是在模型生成时轻微影响 token 的选择，靠统计信号判断一段文字是否由模型写出，文本越长信号越强。对应欧盟《人工智能法案》第 50 条对合成内容的标注要求，存量系统的合规截止日是 12 月 2 日。

平台在重设默认项

🔴 OpenAI — 12 月起 ChatGPT 与 Codex 共用同一个 token 额度，智能体干活第一次和聊天抢同一份预算。10 月 31 日 OpenAI 帮助中心上线《Understanding ChatGPT and Codex usage limits》：Plus、Pro、Business 三档的用量额度在 ChatGPT 与 Codex 之间共享，不再分别计算，统一以 token 计量——模型越高级、任务越复杂消耗越多；即时对话（Instant chat）不计入。ChatGPT Work 里的多步智能体操作计入同一个池子，用户可在"设置—用量"查看合并后的余额与重置时间，用完只能等重置、升级套餐或购买 credits。文档未给具体上线日期，也未公布各档套餐的 token 数。此前四周 Codex 用户几乎隔天收到一次额度重置，10 月 30 日结账页面已出现相关提示。按条数计费的那把保护伞撤了，智能体的每一次多步尝试开始明码标价。

🟡 xAI — 11 月 7 日起 Grok API 输出的文本默认加隐形水印，覆盖七款模型并延伸到工具调用参数。涉 grok-4.7、4.6、4.5、4.3 及 grok-4.20 的推理版、非推理版与多智能体版，Responses 与 Chat Completions 端点全部生效，普通回复、结构化输出与工具调用参数都带；不是塞隐藏字符，而是在生成时轻微影响 token 选择，开发者无需改代码，响应头 x-watermark 为 true 即表示已加。团队管理员可按模型关闭，但需自行确认用途符合法律例外情形，并独自承担标注与披露责任；SuperGrok、X Premium 等消费端订阅不受影响。xAI 称此举为响应欧盟《人工智能法案》：透明度规则自 2026 年 8 月 2 日起适用，存量提供者的合规截止日是 12 月 2 日。三家做法各不相同——Anthropic 的 Claude API 自 11 月 3 日起对 Mythos 5、Opus 4.7/4.6、Sonnet 4.6 加水印且无法关闭，OpenAI 的 API 默认关闭、由开发者自行开启。同一项义务三种写法，且检测接口都只向特定机构开放：这段是不是 AI 写的，正在变成可核查的事实，但只有出钱的人查得到。

🟡 DeepSeek — Harness 团队公开 Super-agent 架构并开源原型，把"一个人只能同时跟进 3 至 5 个会话"当成要解决的问题。10 月 31 日晚发布技术文章《Super-agent 设计探索：迈向更自主的 Agent 系统》：采用 Router 与 Worker 双层结构，Router 作为持续运行的全局协调节点，统一接收群聊、GitHub、邮件等多渠道消息并分派任务，Worker 各自维护独立上下文，并行执行问题复现、代码审查、功能开发，必要时可调用 Subagent；同时引入事件驱动与两级过滤，让 AI 在无人 @ 的情况下也能识别群聊中的潜在缺陷、主动在后台复现并尝试修复。团队强调这是一次面向工程实践的架构探讨而非产品介绍，其内部 Super-agent 实例已在研发中持续运行，参与问题修复、代码审查响应与 Harness 自身的迭代。判断很清醒：多任务的上限已经从模型能力转移到人的注意力，要提效就得先把"人肉调度"这一层搬走。

🔴 腾讯优图 — 5B 全模态解析模型放出技术报告，音频与乐谱两项跑赢了 Gemini-3-Pro。10 月 29 日发布 Youtu-Parsing-Omni 技术报告（arXiv:2610.39301），次日在 Hugging Face 日榜升至第二。核心是"一个编码器、一套坐标系"：像素与 log-mel 音频帧经各自的薄适配层进入共享双向 Transformer，共用同一套 (t, h, w) 位置编码，视频帧的 t 取帧序号、音频块的 t 取时间偏移，跨模态对齐在编码器内完成而不是交给解码器重建；训练用 OSAD（OmniSchema-Aware On-Policy Distillation），学生采样自己的解析结果、由冻结的参考副本打分，每轮结束把 LoRA 合并、学生变老师，无需人工设计奖励。成绩：OmniDocBench v1.6 综合 96.96 居首；OmniParsingBench 75.08 排第二、开源第一，其中音频 78.08 高于 Gemini-3-Pro 的 76.74，乐谱转录 PDMX-Synth 的 CER 22.73 略优于专用音乐模型 LEGATO 的 23.30。对内容行业的意义在于：声音第一次和图像、文字进了同一套坐标体系，"听得出、看得见、还对得上时间"成了一个模型的基础能力。 🎵

🔴 Critical Software — 以 AI 为由"重构"公司，裁掉约 200 人，岗位定义从"写代码"改成"做验证"。这家总部位于葡萄牙科英布拉、做航空与汽车高可靠系统的公司，联合创始人兼董事长 Gonçalo Quadros 对 Lusa 与 Público 表示公司正在因 AI"重新创立"自己，并明确划出 AI 之前与 AI 之后的分界线。他称 AI 现在做测试与系统行为检查的效率"极其凶悍"——两到三年前还不存在这种能力，AI 产出的代码质量同样"凶悍"，因此不久的将来大部分软件将由机器完成；人的角色从创造者变为验证者，集中在失败即不可接受的安全关键系统上：防止列车闯红灯或控制飞机驾驶舱的系统，即便代码由算法生成，设计、验证与确认仍需人来做。他同时给出一句警告：若机器实现递归自我改进且控制失守，"我们可能正站在深渊边缘"。产能可以放大十倍，但签字确认的那一步没有被外包。
